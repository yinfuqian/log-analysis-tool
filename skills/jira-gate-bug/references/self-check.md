# 自查结果判定规则

「自查结果」指**提单人或研发在缺陷单评论区留下的排查记录**。本条规则决定缺陷单是「正常流转」还是「自动调用故障分析」。

## 1. 什么算有效自查结果

一条评论必须**同时**满足三类关键词，才算有效自查结果：

| 类别 | 含义 | 默认关键词 |
|---|---|---|
| 自查动作 | 明确说明这是自查/自检记录 | 自查、自检、自我排查、自测 |
| 结论 | 给出判断，而不是只有动作 | 结论、结果、通过、正常、无异常、已定位、已确认、已修复、根因、原因 |
| 证据 | 说明依据，可被他人复核 | 日志、截图、复现、环境、版本、时间点、步骤、附件、操作、报错 |

判定命令：

```bash
node <技能目录>/scripts/jira-cli.mjs selfcheck <KEY|URL>
```

返回 `{"found": true, "matches": [...]}` 即认为存在有效自查结果；`matches[0]` 会带有评论 id、作者、时间与一行摘要，写评论时直接引用它。

## 2. 什么不算（必须继续自动分析）

- 只有「已自查」「自查过了」而没有结论与证据。
- 只有「我看看」「稍后处理」「已收到」这类无结论回复。
- 结论与证据矛盾（例如写「无异常」，但日志里全是 ERROR）。
- 由工具/AI 生成的历史分析评论（例如本技能写下的「缺陷单预检」或「故障分析报告」评论）——这是分析结果，不是提单方自查。
- 评论时间**早于缺陷单最近一次复现时间**，或评论里写的环境/版本与当前缺陷单不一致（视为过期自查）。
- 只有附件没有文字说明，且附件本身不能自证结论。

出现上述情况时：在评论里说明「自查结果无效/过期」及理由，然后继续执行自动故障分析。

## 3. 判定示例

**有效**

```text
【自查结果】结论：确认为工单回调超时，不是前端问题。
证据：2026-09-19 21:10 的 server.log 里 callback timeout，本地复现 3/10 次；已上传日志 server-20260919.log。
```

**无效**

```text
已自查
```

```text
收到，我看下
```

```text
（只有一张没有说明的截图）
```

## 4. 自定义关键词

项目有固定自查模板时，在 `jira-config.json` 覆盖关键词，避免误判：

```json
{
  "selfCheckKeywords": {
    "headline": ["自查", "自检", "自测结论"],
    "conclusion": ["结论", "通过", "已定位"],
    "evidence": ["日志", "截图", "复现", "traceId"]
  }
}
```

覆盖后同样要求三类关键词同时命中，不允许只放宽到一类。
