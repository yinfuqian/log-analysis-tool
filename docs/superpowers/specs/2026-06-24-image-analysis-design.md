# 图片识别日志分析设计

## 背景

当前系统只支持上传日志文件进行分析。需要扩展为同时支持图片输入，并且保持现有“拉取代码 -> 定位代码 -> AI 综合分析”的主链路不变。

## 目标

新增图片识别能力，支持用户通过 Windows 客户端以三种方式提供图片：

- 粘贴截图
- 拖拽图片
- 选择图片文件

图片输入分为两类，由用户手动选择标签：

- 日志截图
- 业务截图

系统需要先识别图片内容，再结合代码仓库和分支版本进行分析，最终在现有结果弹窗中展示识别摘要、代码定位和综合结论。

## 方案

采用“新增独立图片入口 + 复用现有分析主链路”的方案。

- 日志文件继续走现有 `/logfile/upload`
- 图片新增独立上传入口
- 图片上传后返回统一的任务输入路径和元数据
- 异步分析任务根据 `source_type` 分流处理
- 图片识别结果被整理成统一的“分析上下文文本”，再复用现有代码分析能力

## 后端设计

### 图片上传

新增图片上传接口，负责：

- 校验图片类型，仅支持 `png/jpg/jpeg`
- 生成唯一文件名并保存到本地存储目录
- 记录上传元数据
- 返回统一字段：
  - `file_path`
  - `log_id`
  - `source_type=image`
  - `image_tag`
  - `image_description`
  - `message`

### 异步分析分流

`/analysis/submit_async` 扩展支持：

- `source_type=file|image`
- `image_tag=log_image|business_image`
- `image_description`

异步任务内部新增两条输入链路：

1. 文件模式
   - 保持原有逻辑

2. 图片模式
   - 读取图片文件
   - 调用多模态模型识别图片
   - 输出统一的图片识别结构
   - 将识别结果转成“分析上下文文本”
   - 提取组件线索、错误关键词、可疑调用点
   - 进入现有综合分析链路

### 图片识别输出

为了兼容后续代码定位，图片识别输出统一结构：

- `source_type`
- `image_tag`
- `summary`
- `extracted_text`
- `keywords`
- `components`
- `analysis_text`

其中：

- 日志截图偏重 OCR 与异常日志段提取
- 业务截图偏重界面语义理解、报错文案、关键业务状态和用户补充描述

### 代码定位

原逻辑依赖日志堆栈。图片模式需要放宽：

- 有堆栈时优先按堆栈定位
- 无堆栈时使用 `keywords/components` 在代码仓库中检索调用点
- 即使没有明确代码片段，也允许继续输出图片分析结论，不再直接失败

### 返回结果

分析结果新增：

- `source_type`
- `image_tag`
- `image_analysis`

这样客户端可以把“图片识别摘要”放进结果弹窗顶部展示。

## 客户端设计

### 输入模式

新增输入模式选择：

- 日志文件
- 图片识别

### 图片模式字段

图片模式显示以下控件：

- 图片标签：日志截图 / 业务截图
- 图片描述输入框
- 图片路径展示
- 选择图片按钮
- 粘贴图片按钮
- 清空图片按钮
- 拖拽提示区

### 上传行为

- 文件模式调用日志上传接口
- 图片模式调用图片上传接口
- 两种模式都复用现有“开始分析”按钮

### 结果展示

分析弹窗新增“图片识别摘要”导航节点，用于展示：

- 图片类型
- 图片描述
- 识别出的文本
- 提炼出的关键现象

## 错误处理

- 图片格式不支持时立即提示
- 粘贴板没有图片时提示用户
- 图片识别失败时返回明确错误
- 图片临时文件和代码临时目录在任务结束后统一清理
