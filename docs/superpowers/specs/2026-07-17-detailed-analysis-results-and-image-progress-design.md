# 详细分析结果与图片进度设计

## 目标

恢复独立的“结论”和“问题明细”，让 Windows 弹窗与 HTML 报告完整展示每个问题，并提供三级目录；图片分析期间始终显示进度，同时在本地 OCR 失败或阻塞时安全降级到原图多模态分析。

## 结果结构

- 一级目录：结论、问题明细、分析依据、代码定位结论、问题结论、日志分析、相关代码片段、任务信息等实际存在的章节。
- 二级目录：问题明细下的“问题1 · 标题”“问题2 · 标题”。
- 三级目录：每个问题下实际存在的现象摘要、根因判断、分析依据、修复建议、排查命令、修复命令、相关代码。
- 结论保留总体分类、置信度、知识库命中、总体根因和总体建议；不再被问题列表替换。
- Windows 弹窗和 HTML 导出使用相同的问题字段与目录层级。

## 图片进度与 OCR 降级

- 进度条放在图片表单之前，日志和图片模式始终可见。
- 图片任务显示上传、Git 克隆、OCR、日志提取、代码定位、AI 分析等后端阶段。
- 单张或全部图片预测异常时记录警告；全部图片 OCR 失败时返回 `available=false`，阻止错误的上下游链路结论。
- 最终分析继续携带原图调用多模态模型，因此 OCR 失败不终止整次任务。
- Python 3.13 本地 PaddleOCR 原生预测存在长时间阻塞风险；运行环境统一建议 Python 3.10，与 Docker 基础镜像一致。

## 验证

- 单元测试覆盖独立结论/问题明细、三级目录、弹窗问题正文、HTML 三级锚点、图片模式进度布局和 OCR 全失败降级。
- 使用现有 Windows 客户端和后端相关测试做回归。
